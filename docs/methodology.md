# 数学研究の自動化: 本リポジトリの方法論

「AI に数学の未解決問題を解かせる」を、再現可能な工程に落とすための覚書。
調べたベストプラクティスと、実際に p0000〜p0003 を回して分かったことを混ぜて書く。

## 0. 出発点: 2026 年のヤコビアン予想の反例

2026 年 7 月 19 日、3 変数の明示的な多項式写像としてヤコビアン予想の反例が公表された
(`p0000_jacobian_2026` の `survey` に出典)。この事例が方法論として重要なのは、
**結果が有限の対象 1 個に落ちている**点である。反例写像 $F$ さえあれば、

* ヤコビ行列式が 0 でない定数であること
* $F$ が単射でないこと

は誰でも独立に確かめられる。探索がどれほど巨大でも、検証は小さい。
逆に言えば、**この形に落ちない結果は自動化に向かない**。本リポジトリは
「有限証明書に落ちる問題だけを扱う」という制約を最初に置いている。

## 1. 五つの設計原則 (README と対応)

1. **主張は有限証明書に落とす。** 結果は「対象 (JSON)」と「検証手続き」の 2 つ組。
   浮動小数点数は証明書に入れない (整数・有理数・代数的数のみ)。
2. **検証器は探索器と実装を共有しない。** `mar.checkgraph` は標準ライブラリだけで
   書き、`mar.search` を import しない。アルゴリズムも意図的に変える
   (探索: 分枝限定 / 検証: 極大独立集合の全列挙、探索: マッチングの分枝 /
   検証: 線グラフへの還元)。共通のバグが両方をすり抜ける確率を下げるため。
   **定数も共有しない**: 「$n \le 10$ の連結グラフを全部読んだ」の根拠になる
   OEIS の公表値は、検証器が自分の表 (`checkgraph.PUBLISHED_*`) を持つ。
   探索器が書いた期待値と突き合わせると「探索器の表に探索器の出力が一致した」
   という無内容な検査になる。
3. **先行研究ゲート。** `Problem.survey.evidence` が空なら `mar search` は動かない。
   計算探索の最大の失敗は誤りではなく**既知の結果の再発見**である。
4. **検証に落ちた証明書は論文化しない。** `mar paper` は verify を再実行する。
5. **数値は本文に直書きしない。** 論文本文は証明書 JSON から生成する。
   人手で書いた数字と計算結果がずれる事故を構造的に潰す。

## 2. テーマ選定

自動化が効くのは次の条件を満たす問題である。

| 条件 | 理由 |
|------|------|
| 反例が有限の対象 1 個 | 反証が「見つけて渡す」だけで閉じる |
| 対象の完全リストが第三者から公開されている | 網羅性の根拠を自前の同型判定に依存しない |
| 不等式が**片側** | 証人つき検証 (§3) が使える |
| 未解決性の出典が明示できる | 原則 3 のゲートを通せる |

実際に使った素材:

* **TxGraffiti の予想リスト** (arXiv:2507.17780)。自動予想生成系が出した予想が
  「未解決」「解決済み」のラベル付きで並んでおり、原則 3 のゲートを通しやすい。
  p0001 (予想 3)、p0002 (予想 2)、p0003 (予想 4) はここから採った。
* **B. McKay の組合せデータ** (連結グラフ・木の完全リスト)、**GENREG** (正則グラフ)。
  「$n \le 10$ の連結グラフを全部見た」の根拠を OEIS の公表個数との突合で示せる。

避けるべき素材: 解析的な評価だけで閉じる主張、無限族の構成、
「十分大きい $n$ で成立」型の主張。有限証明書に落ちない。

### 未解決性の一次情報源は予想リストの本家である

WOWII の予想の状態は **DeLaViña 本人が管理する
`open.html` / `resolved.htm`** が一次情報源であり、
google-deepmind/formal-conjectures の `@[category research open]` タグは
**そのミラーであって遅れる**。実例:

* **予想 146** は 2026-07-21 付で `resolved.htm` に移っていたが、
  formal-conjectures では 2026-07-27 時点でも open のままだった。
  p0005 の走査 (07-26) はこれを未解決と扱ってしまい、
  論文に注意書きを足して訂正した。
* **予想 140** (星の下界 $1 + \ell_{\max} \le \mathrm{tree}$) は `open.html` に
  status **E** (証明済み) で載っている。p0007 / p0008 はこの不等式を
  補題として使うので、**自分の補題として書かず 140 として引用**する。

したがって `survey` のゲートでは **本家の 2 ファイルを両方引き、取得日を
証拠に残す**。formal-conjectures だけを根拠にしない。

## 3. 証人つき検証 (witness-based certificate)

本リポジトリで一番効いた工夫。$Z(G)$ (ゼロ強制数)、$\alpha(G)$ (独立数)、
$\mu^*(G)$ (飽和数) はいずれも計算が NP 困難で、素朴に
「探索器の計算を検証器がやり直す」と検証コストが探索コストと同じになる。
だが**片側の不等式**なら、証人を渡せば検証は線形時間になる。

| 主張 | 証人 | 検証器がやること |
|------|------|-----------------|
| $Z(G) \le \alpha(G)+1$ | 独立集合 $A$ と ゼロ強制集合 $S$ ($\lvert S\rvert \le \lvert A\rvert+1$) | 独立性の判定 + 強制過程の実行 |
| $\mu^*(G) \le H(G)$ | 極大マッチング $M$ ($\lvert M\rvert \le H(G)$) | 極大性の判定 + 次数の和 |

$\alpha(G) \ge \lvert A\rvert$ と $Z(G) \le \lvert S\rvert$ は定義から従うので、
NP 困難な最適化を検証器が解き直す必要がない。探索器がどんな発見的手法を
使ったかは検証に無関係で、嘘をつけば「証人が条件を満たさない」で落ちる。

**逆向きは閉じない。** 「反例である」「等号が成立する」は下界を要するので、
証人だけでは検証できない。ここで「大きい族は探索器を信用する」と書いてしまうと、
検証済みに見えて実は未検証の数字が論文に載る。避けるための型が 2 つある。

### 例外リスト方式 (p0002 の等号分類)

逆向きが必要になる対象を**漏れなく列挙して証明書に載せる**。検証器は

* リストに載ったものだけ厳密に再計算する ($Z = \alpha+1$ を確かめる)、
* 載っていないものは証人が**より強い**条件を満たすことを確かめる
  ($|S| \le |A|$、これで $Z \le \alpha$ が片側に閉じる)

の 2 つを行う。後者は線形時間なので、族が何万個あっても分類全体が閉じる。
NP 困難な計算を検証器が解くのは例外の個数 (p0002 では 46 個) だけ。
探索器が例外を隠せば、隠されたグラフで $|S| \le |A|$ が破れて検出される。

### 上下から挟む方式 (p0003 の最大比)

「族内の $\max \mu^*/H$ は $R$」のような**最大値**の主張は、

* 上から: 証人が各グラフに $\mu^* \le |M|$ を与えるので、
  $\max |M|/H \le R$ を全数について線形時間で確かめれば真の最大値 $\le R$、
* 下から: 最大を達成すると主張されたグラフ 1 個だけ $\mu^*$ を厳密に計算し、
  $\mu^*/H = R$ を確かめれば真の最大値 $\ge R$

の 2 つで確定する。**探索側も同じ不等式で枝刈りできる**のが利点で、
「証人の上界が現在の最大を超えないグラフは最大になり得ない」から、
厳密計算は最大値が小さいうちの数十個で済む。

この設計に切り替える前は、最大比を「厳密計算に進んだグラフ」からしか
集計しておらず、その集合に入らない族で値を取りこぼしていた。
片側評価で足切りした対象を集計に使うときは、**足切りの向きが集計の向きと
合っているか**を必ず確かめる。

どこまでが証人で閉じ、どこからが再計算かは論文の「限界」節に明記する。

### 検証器は「改竄テスト」で担保する

**正しい証明書が通ることは、検証器が何かを検査している証拠にならない。**
何も検査しない検証器でもそれは通る。担保になるのは**嘘の証明書が落ちること**
だけなので、`tests/test_tamper.py` では証明書と証人を実際に書き換えて、
対応する検査項目が FAIL することを確かめる:

* 証人ファイルを 1 バイト反転する → SHA-256 で落ちる
* ハッシュも辻褄を合わせて証人を偽造する → 条件検査 (独立性・極大性) で落ちる
* 等号グラフを 1 個隠す / 等号でないグラフを混ぜる → 例外リスト方式で落ちる
* 最大比を過大にも過小にも書き換える → 上下の挟み込みで落ちる
* 公表値の期待値やグラフ数を偽る → 検証器が独自にもつ表で落ちる

テストは元データの走査量に比例して重くなるので、証明書を小さい族だけに縮めてから
検証器にかける (証人ディレクトリは一時ディレクトリへ差し替える)。

### 手証明も総当たりで照合する

改竄テストが守るのは「検証器が嘘を落とすか」だけで、**論文本文に書いた定理の
主張そのもの**は守らない。手証明は人 (と AI) が書く以上、代数の書き損じや
境界条件の見落としが混入しうる。そこで `tests/test_hand_proofs.py` は、
証明書も探索器も読まずに、元データを総当たりして主張を直接照合する:

* $\alpha \le 2$ なら仮定が成り立ち traceable (定理)
* 仮定を満たすなら $n < (1+\bar{d})^2$ (密度条件)
* $n \ge 5$ の木では仮定が空虚 (系)
* 仮定を満たす連結二部グラフは $x - y \le 1$ と辺数の下界を満たす (縮約)
* $K_k$ + 懸垂頂点は仮定を満たし traceable だがハミルトン閉路をもたない (最良性)

「証明書が通る」ことと「定理が正しい」ことは別の主張なので、テストも別に置く。
論文の数値は証明書から生成されるが、論文の**定理**は生成されない — 人が書いた
文章である以上、そこにだけ検証の穴が残る。

この形のテストは設計の穴も見つける。実際、**最大比を達成するグラフが走査した族の
要素であることを確かめていない**という抜けがここで露見した。証明書が名指しした
graph6 をそのまま厳密計算しても、族外のグラフを持ち出されれば上界と下界が
「別の対象について」一致してしまう。修正は「達成グラフを検証器が走査中に自分で
捕まえ、証明書の名指しと一致することも確かめる」。
**下界の対象は、証明書に書かせるのではなく検証器が選ぶ。**

**実務上の利点**: p0003 では、貪欲な極大マッチングだけで大多数の判定が付き、
厳密計算まで進んだのは全体の数割だった。片側の不等式は「安いヒューリスティクスで
ほとんど片付け、残りにだけ厳密解を使う」設計にできる。

## 4. 証人の置き方

* 族 (位数・種別の組) ごとに 1 本のバイナリファイル (`data/witnesses/`)。
* 元データの**列挙順**に固定長レコードを並べる。検証器は元データを走査しながら
  先頭から消費するので、索引を持たなくてよい。
* ファイルの SHA-256 とレコード数を証明書 JSON に書く。証明書だけが真実の所在。
* 大きい族は gzip で書く (p0003 の $n = 10$ は生 117 MB が 1/10 以下になる)。

### 1 つの証人で複数の予想を閉じる (p0005)

証人は「主張 1 つに 1 個」である必要はない。**左辺が多項式時間で計算でき、
右辺が同じ量の単調関数**である予想は、その量の下界を与える証人 1 個で
まとめて閉じる。p0005 は $\mathrm{tree}(G)$ (最大誘導木の位数、NP 困難) の
下界を主張する WOWII 予想 142・144・146 を、グラフごとに**木を誘導する頂点集合
1 つ**で同時に検証している。走査コストは 1 本ぶんしか増えない。

このとき等号の分類は予想ごとに別のリストになるので、証明書には
`equality_graphs: {予想 → [graph6]}` の形で持ち、検証器は「どの予想で等号か」
まで一致することを要求する。予想を取り違えた証明書が通らないことは
改竄テストで確かめる
(`test_p0005_equality_moved_to_another_conjecture_is_detected`)。

### 含意を 2 種類の証人で閉じる (p0006)

p0004 / p0005 の予想は「左辺 $\ge$ 右辺」という**不等式 1 本**だった。WOWII
予想 194 は形が違う:

$$\alpha(G) \le 1 + \ell_{\mathrm{avg}}(G) \;\Longrightarrow\; G \text{ は traceable}$$

仮定にも結論にも NP 困難な量が入っている ($\alpha$ の計算と、ハミルトン路の
存在判定)。素直に検証すると 1340 万個すべてで $\alpha$ を厳密計算することに
なり、検証が探索より高くつく。

含意は「結論が真」か「仮定が偽」のどちらかを示せば閉じる。そこで**証人を
2 種類**用意し、どちらを使ったかをグラフ 1 個あたり **1 ビット**で記録する:

| モード | 証人 | 検証 | 閉じる理由 |
|--------|------|------|-----------|
| 0 | ハミルトン路 (頂点列) | 線形 | 結論が真 |
| 1 | 独立集合 $T$ ($n\lvert T\rvert > n + S$) | 多項式 ($S$ の再計算が支配的) | $\alpha \ge \lvert T\rvert$ より仮定が偽 |

**どちらの経路も $\alpha$ を計算しない。** これが設計の要点で、NP 困難な量が
仮定側にあっても検証を多項式時間に保てる。$\ell_{\mathrm{avg}} = S/n$ の分数を
避けて $n\alpha \le n + S$ の整数形で扱うので、比較はすべて厳密整数演算になる。

探索器も $\alpha$ を計算しない。$k_{\min} = \lfloor (n+S)/n \rfloor + 1$ と
置くと

$$\text{大きさ } k_{\min} \text{ の独立集合が存在する} \iff \text{仮定が偽}$$

なので、決めるのは「サイズ $k$ の独立集合はあるか」という**判定**だけでよく、
最大独立集合を求める必要がない。見つかった辞書式最小の集合がそのまま
モード 1 の証人になる。

第 3 の選択肢は「反例」——仮定が成り立つのに路が無いグラフ——で、これだけは
証明書に graph6 と $(\alpha, n\alpha, n+S)$ を明示列挙し、検証器が厳密に
再現する (例外リスト方式の再利用)。したがってモードビットは嘘をつけない:

* モード 0 と偽れば、実在しないハミルトン路を出す必要がある。
* モード 1 と偽っても、そのグラフは仮定を満たすので任意の独立集合 $T$ で
  $n\lvert T\rvert \le n\alpha \le n+S$ となり、**どんなマスクを充てても**
  検査を通らない (`test_p0006_mode_bit_flipped_to_mask_is_detected`)。

なお「仮定を満たすグラフが何個あったか」は、モード 0 の個数として自動的に
閉じる。予想の中身が実際に問われているのは Chvátal–Erdős の系の射程外
($\alpha \ge 3$) の部分だけなので、その内数も検証器側で独立に数え直す。

分類の深さは族ごとに 2 段階に分ける。**分類する族**(連結グラフ全体と正則
グラフ)では検証器がモード 0 のグラフすべてで $\alpha$ を厳密再計算し、
仮定が本当に成り立つこと・等号がどこで起きるかまで閉じる。**分類しない族**
(木)では、系「$n \ge 5$ の木は仮定を満たさない」を手証明してあるので全数が
モード 1 になり、主張は「仮定が空虚」だけで済む。証明書はどちらの段かを
`classified` で持ち、検証器は段に応じて検査を切り替える。

この 2 段構えには副産物がある。$\alpha \ge 3$ の内数は、分類する族では
$\alpha$ の厳密計算から、分類しない族では極大独立集合の列挙から、**独立な
2 通りの実装**で数えている。実データでは後者の経路が 1 度も走らない (木の
仮定成立数が 0 だから) ので、テストでは族を人為的に分類なしへ落として
両者が同じ値を出すことを確かめている
(`test_p0006_deep_count_agrees_between_the_two_tiers`)。

### 等式の仮定を手証明で片側に潰す (p0007)

WOWII 予想 200 の仮定は不等式ではなく**等式**である:

$$\mathrm{tree}(G) = \bigl\lceil 1 + \ell_{\mathrm{avg}}(G)\bigr\rceil =: t(G).$$

等式を否定するには素朴には両側が要る。$\mathrm{tree}(G) > t$ の側は誘導木 1 つで
閉じるが、$\mathrm{tree}(G) < t$ の側は「これより大きい誘導木は存在しない」という
**NP 困難な量の上界**で、短い証人がない。つまり「仮定が偽」を安く示せる保証が
そもそも無い。

ここを開けるのが**手証明**である。星の下界 (論文 §3) は、頂点 $v$ と $N(v)$ の
最大独立集合 $A$ に対し $\{v\} \cup A$ が星を誘導することから

$$\mathrm{tree}(G) \ \ge\ 1 + \ell_{\max}(G) \ \ge\ 1 + \ell_{\mathrm{avg}}(G)$$

を与え、$\mathrm{tree}$ が整数なので $\mathrm{tree}(G) \ge t(G)$ が常に成り立つ。
この 1 本で下側が消え、等式が片側に潰れる:

$$\text{仮定が偽} \iff \mathrm{tree}(G) > t(G) \iff \text{位数 } t+1 \text{ の誘導木が存在する}.$$

| モード | 証人 | 検証 | 閉じる理由 |
|--------|------|------|-----------|
| 0 | ハミルトン路 (頂点列) | 線形 | 結論が真 |
| 1 | 位数 $t+1$ の誘導木のマスク | 線形 | $\mathrm{tree}(G) > t$ より仮定が偽 |

**手証明が証人設計を可能にしている**のがこの問題の要点で、仮定が最初から不等式
だった p0006 とは事情が違う。定理を 1 本足すことが、検証を指数から多項式へ落とす
実装上の手段になっている。

副作用として、NP 困難な $\mathrm{tree}(G)$ の厳密計算は**モード 0 のグラフだけ**
で走る。モード 1 のグラフはマスク 1 枚で落ちるので、分類の費用は仮定が成り立つ
側だけに閉じ込められる。探索側も同じ構造を使い、貪欲で位数 $t+1$ の誘導木が
取れた時点で打ち切って厳密解を呼ばない。

問題の**選び方**にも同じ節約が効いている。予想 200 に要る不変量
($\mathrm{tree}$ は p0005、$S$ は p0006) はどちらも実装済みなので、`checkgraph.py`
に 1 行も足さずに書けた。次節のとおり検証器を触ると過去の検証記録が全部失効する
ので、「検証器が既に知っていること」で書ける予想を優先するのは、数学的な面白さ
とは別の、運用上の選択基準になる。

### 予想を手証明で閉じたときの走査の役割 (p0008)

p0008 (WOWII 予想 141) は、走査より先に**予想そのものの証明**が付いた最初の
問題である。こうなると走査の意味が変わる。反例を探す作業ではなくなり、
**証明の各ステップを機械照合する**作業になる。

証明を、検証器が独立に再計算できる粒度の主張へ分解して並べる。

| 証明のステップ | 検証器がやること | 費用 |
|---------------|-----------------|------|
| 内周 $\ge 4$ $\Rightarrow$ $\ell_{\max} = \Delta$ | 両辺を計算して一致を見る | 多項式 |
| 球の補題: $r = \lfloor g/2 \rfloor - 1$ なら $G[B_r(v)]$ は木 | **全頂点**で $B_r(v)$ を作り、辺数 $= \lvert B_r \rvert - 1$ を見る | 多項式 |
| 主定理: $\lvert B_r(v^*) \rvert \ge \Delta + r$ | 最大次数の頂点で球の大きさを数える | 多項式 |
| 等号 $\iff$ 内周 4 かつ $\mathrm{tree} = 1 + \Delta$ | 等号グラフだけ厳密再計算、**他は狭義不等式**を要求 | 等号のみ指数 |
| Moore 型の強化 | 球の大きさと $1 + \Delta\sum(\delta-1)^i$ を比較 | 多項式 |

要点は 2 つある。

* **証明が正しければ全部通る、間違っていれば具体的な反例が出る**。実際、
  球の半径を $\lceil g/2 \rceil - 1$ と書き間違えたまま実装しかけたが、
  $C_5$ が $B_2(v) = V$ で落ちるので手計算の段階で捕まった
  (`test_ball_radius_cannot_be_rounded_up` として恒久化)。
  走査は証明のタイプミス検出器として働く。
* **論文の主張は「$n \le 10$ で反例なし」ではなく「全グラフで成立」になる**。
  走査結果は主張の根拠ではなく、証明の傍証と等号ケースの分類として §4 に置く。
  §7 の 3 分類には収まらない 4 番目の「結果」である。

なお手証明が出たら、その不等式が**既に知られていないか**を必ず確かめる。
予想 141 の出発点である星の下界は WOWII 予想 140 (status E) そのもので、
自分の補題として書いていたら誤った新規性の主張になっていた。

### NP 困難な量を「局所版の予想」へ逃がす (p0009)

p0009 (WOWII 予想 2) の右辺は葉数 $L_s$ で、決定は NP 困難である。この型の
予想は 2 つの意味で扱いにくい: (a) 反例探索が全域木の最適化になって高価、
(b) 手証明のとっかかりが「$L_s$ の下界を作る」しかない。p0009 で採った
手順は、この 2 つを同時にほどく型になっている。

1. **証人が立つ下界を手証明する。** 定理 3.2 (任意の辺 $uv$ で
   $L_s \ge \lvert N(u) \cup N(v)\rvert - 2$) は、二重星を全域木へ延長する
   1 行の補題で出る。証人 (葉集合) は探索器がこの証明どおりに作れる。
2. **その下界で予想を割ると、NP 困難な量が消えた主張が残る。** ここでは
   $f(G) = \max_{uv \in E}\lvert N(u) \cup N(v)\rvert \ge 2\overline{\ell}(G)$
   (予想 B')。B' $\Rightarrow$ 元の予想であり、B' には全域木の最適化が
   現れない ($f$ は $O(nm)$、$\ell$ は各頂点の近傍に閉じた計算)。
   ただし $\ell(v) = \alpha(G[N(v)])$ 自体は一般には NP 困難であり
   (apex 頂点を足せば $\ell(v) = \alpha(H)$)、これは**元の予想の左辺にも
   もともとある量**である。消えたのは $L_s$ のほう。
3. **走査は両方を同時に照合する。** 元の予想は証人 1 個で、B' は検証器の
   再計算で確かめる。B' の等号 (8,796 個) は元の予想の等号 (13 個) より
   桁違いに多く、**どちらの不等式がどこで緩いか**が分離して見える。
4. **部分的な証明は「帯」で書く。** $2S \le 4n$、$2S \le n(\Delta+2)$、
   $n\sum_v d(v)\ell(v) \ge 2mS$ の 3 帯は初等的に閉じる (定理 5.1)。
   閉じた割合 (99.9999%) を数えると、残りがどんなグラフか
   ($\delta \ge 4$ で $d$ と $\ell$ が負に相関する 14 個) が言語化でき、
   限界節が具体的になる — 実際この規模なら graph6 で全部名指しできる。

一般化すると: **NP 困難な不変量 $X$ の下界 $X \ge g(G)$ を証人つきで手証明
できれば、予想 $X \ge h(G)$ は $X$ を含まない強い予想 $g \ge h$ に帰着
できる**。$g$, $h$ が安く計算できるなら判定も安くなるが、そうでなくても
「大域的な最適化が消える」だけで探索は桁で速くなる。帰着先が偽なら反例が安く見つかり (探索の高速化)、真なら
元の予想が証明される。どちらに転んでも進む。実際 p0009 では、証人の
99.999% が 1 段目の二重星のままで足り、厳密な $L_s$ の計算は 1340 万個中
13 回で済んだ。

この型を選ぶときの注意: 帰着先の強い予想は**元より真に強い**ので、反例が
出ても元の予想は死なない。論文ではその非対称性 (B' の反例は元の予想の反例
ではない) を明示する。

### 予想は強くすると証明しやすくなることがある (p0009)

上の帰着で B' まで来ても、$\max$ が残っているうちは手が止まる。$\max$ は
「どの辺で達成されるか」を知らないと下から評価できず、数え上げの議論と
相性が悪いからである。p0009 で効いたのは、**max を平均に置き換えてさらに
強い予想を作る**という一手だった。

$$\underbrace{2(\overline{\ell}-1) \le L_s}_{\text{予想 2 (NP 困難)}}
\;\Longleftarrow\; \underbrace{\max_{uv \in E}\lvert N(u)\cup N(v)\rvert \ge 2\overline{\ell}}_{\text{B' (局所・max)}}
\;\Longleftarrow\; \underbrace{n\sum_{uv \in E}\lvert N(u)\cup N(v)\rvert \ge 2mS}_{\text{A (局所・平均)}}
\;\Longleftarrow\; \underbrace{\mathrm{Cov}(d,\ell) \ge 0}_{\text{共分散}}$$

A は B' より真に強い (平均 $\ge$ 閾値ならば max $\ge$ 閾値) が、左辺が
$\sum_{uv \in E}$ の形なので**辺ごとの包除がそのまま使える**:
$\sum_{uv \in E}\lvert N(u)\cup N(v)\rvert = \sum_v d(v)^2 - 3T$ ($T$ は
三角形数)。ここから Gallai の $\tau_v = d(v) - \ell(v)$ を通して
$\sum_v d(v)\ell(v)$ まで落ち (補題 4.3、等号は三角形なしと同値)、A は
$d$ と $\ell$ の共分散が非負であるという 1 行の主張になる。三角形が
なければ $\ell = d$ なので共分散は分散で、自明に非負 — 以前
Cauchy--Schwarz で個別に証明していた三角形なしの場合が、この形の系として
2 行で出る。

数値的な効果も大きかった。$\Delta$ 帯までで 99.656% だったものが、共分散帯
を足した瞬間 99.9999% (残り 14 個) になった。**強い予想のほうが証明の道具が
増える**という現象は、帰納法の仮説を強めると証明が通る話と同じ構図である。

運用上の型:

1. 元の予想が $\max$ / $\min$ を含むなら、**平均版を作って先に攻める**。
   平均版 $\Rightarrow$ max 版は無料 (平均を超える要素が存在する)。
2. 平均版の両辺に $\sum$ が立ったら、**包除・二重数え上げ・既知の恒等式**を
   総当たりで当てる。ここが max 版では踏めなかった段。
3. 落ちた先が既知の量 (ここでは共分散) なら、**その量が非負になる十分条件**
   (三角形なし $\Rightarrow$ $\ell = d$) を系として回収する。
4. 走査は**梯子の全段**を同時に照合する。A の反例・等号と B' の反例・等号を
   別々に数えると、どの段がどこで緩いかが分離して見える (p0009 では A と
   B' の等号がどちらも 8,796 個で一致し、段の間に隙間がないことが分かった)。

### 検証記録は検証器のコードのハッシュで無効化される

`data/verifications/*.json` は証明書ダイジェストと**検証器のソース
(`checkgraph.py`, `exact.py`, `certificate.py` + 問題モジュール) のハッシュ**の
両方で鍵付けしている。新しい問題の検証コードを `checkgraph.py` に追記すると、
そのハッシュが変わるので**過去の問題の検証記録がすべて無効化**される
(p0005 の追記で p0003 / p0004 の記録が失効した)。粒度の粗さは意図的で、
「検証器を触ったら記録を信じない」側に倒してある。`mar paper` は既定で
再検証するので、失効した記録があっても論文は正しく再生成される。
古い問題の記録を回復したいときは `mar verify` を再実行する
(p0004 の場合で約 25 分)。

## 5. 落とし穴 (実際に踏んだもの)

| 症状 | 原因 | 対策 |
|------|------|------|

| 検証結果を印字した瞬間に落ちる | Windows の標準出力が cp932 | `sys.stdout.reconfigure(encoding="utf-8")` |
| LaTeX が `Missing $ inserted` | graph6 は `~ ^ _ { } \` を普通に含む | `mar.report.texescape` で一元的にエスケープ |
| f-string で `SyntaxError` | Python 3.10 は f-string 内にバックスラッシュを書けない | LaTeX 断片は先に変数へ組み立てる |
| 1 グラフに 1 分以上かかる | 「$Z \le \alpha$ のゼロ強制集合が存在しない」ことの全探索 | 互いに素なフォートの個数で下界を取り、枝を捨てる |
| 探索は終わったが主張が薄い | 予想の**片側**しか検証していない | 何が証人で閉じ、何が再計算かを最初に決めてから走らせる |

| 高価な走査の終盤で `HTTPError: 404` (`tree17.2.txt`) | McKay が個別ファイル `tree{n}.{d}.txt` を出しているのは $n \le 16$ まで。$n \ge 17$ は `tree{n}.all.tar.gz` だけ | tar から展開するフォールバックを入れる。**元データの入手は走査を始める前に全族ぶん確かめる** (50 分の走査が最後の 1 族の 404 で消えた) |
| 「反例なし」の分枝が異常に速い / 遅い | 証人を作るヒューリスティクスと厳密解の切り替え条件を間違えている | 「証人が右辺 $+\,1$ に届いたら打ち切る」など、**厳密解に落ちる条件を明示的に数え、証明書に記録する** (p0004 の `exact_calls`) |
| 未解決のはずの予想が実は解決済み | formal-conjectures のタグを一次情報源にした (予想 146 は 5 日前に解決済みだった) | `survey` で **本家の `open.html` と `resolved.htm` を両方**引き、取得日を証拠に残す (§2) |
| 自分の補題が実は既知の予想だった | 手証明が付いた不等式を出典照合しなかった (星の下界 = 予想 140、status E) | 補題を書いたら**同じリスト内の解決済み項目を検索**してから新規性を主張する |
| 中身は同じなのに証人の SHA-256 が合わない | `gzip.open(path, "wb")` が gzip ヘッダに**書き込み時刻**を埋める。走査後に小さいテスト用の探索が同じ族の証人を上書きしただけで検証が FAIL した (p0008 の `graphs_06` / `graphs_07`) | `mar.search.witness.open_witness` で **MTIME = 0** に固定して書く。これで「同じ探索をやり直せば同じバイト列」が言える。回帰テストは `tests/test_witness_repro.py` |

証人の再現性は p0008 以降の既定である。p0003–p0007 の証人はまだ時刻入りで
書かれており、証明書はそのとき出来上がったファイルの SHA-256 を持つ。
リポジトリに入っているファイルとの束縛としては有効なので既存の証明書は
そのままだが、これらは**探索をやり直すと同じ内容で違うハッシュになる**。
書き手を差し替えるなら、証人と証明書を同時に作り直す必要がある。

出典に関する 2 行 (予想 146 が解決済みだったこと、自分の補題が予想 140 だった
こと) は自分では気づけなかった。**書いたコードは観点別の並列レビューにかける**
こと。ここでは「アルゴリズムの正しさ」と「証明書の健全性・検証器の独立性」の
2 観点でレビューさせ、後者だけがこの 2 件を検出した。

## 6. 1 問題を回す手順

```
python -m mar survey  pNNNN_xxx    # 未解決性の出典を確認 (ゲート)
python -m mar search  pNNNN_xxx    # 証明書 JSON + 証人ファイルを生成
python -m mar verify  pNNNN_xxx    # 実装を共有しない検証器で再検査
python -m mar paper   pNNNN_xxx    # verify を再実行してから PDF を生成
```

新しい問題を足すときに書くのは 1 モジュール (`problems/pNNNN_*.py`) と
本文ビルダ (`problems/_pNNNN_paper.py`) だけ。前者に `survey` / `search` /
`verify` / `references`、後者に `build(cert) -> {"ABSTRACT", "BODY"}` を書く。
本文中の数値はすべて `cert.data` から生成する (原則 5)。

## 7. 何を「結果」と呼ぶか

有限範囲の網羅検証は**証明ではない**。それでも次の 3 つは価値がある。

1. **反例の非存在範囲** — 「反例があるなら $n \ge 11$」は次の探索の設計を変える。
2. **等号ケースの分類** — 予想の最良性や、証明の際に相手にすべき族が分かる。
3. **反例の完全分類** — すでに反証された予想でも、反例が何個あってどんな形かは
   別の情報である (p0003)。

いずれも論文の主張として書けるが、**証明と同じ強さの主張に見せない**こと。
「限界」節で走査範囲と、証人で閉じていない部分を明示する。

4 番目として、**予想そのものの証明**がある (p0008 の予想 141)。この場合だけは
走査範囲の限界が主張の限界にならない。ただし §4 のとおり、走査は証明の機械照合
として残す — 主張が全グラフに及ぶぶん、証明のタイプミスが致命的になるからである。
